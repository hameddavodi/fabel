- 2026-09-06 **inprod() precision bug found by parity agent, partially fixed**: `inprod()`'s public signature (`fdobj1, fdobj2, Lfdobj1, Lfdobj2, rng, wtfd`) exposes no `EPS`/`JMAX` knobs -- its help text states its Richardson/Romberg approximation is "good to about four to five significant digits", which is exactly the ~1.3e-4 relative mismatch the parity agent measured against the exact `t(coefs) %*% eval.penalty(...) %*% coefs`. For the 4 B-spline x B-spline cases (`inprod_bspline_L0_0/L1_1/L2_0/L0_2`), fda's public API has an exact alternative for plain-derivative orders on a B-spline basis: `inprod.bspline(fdobj1, fdobj2, nderiv1, nderiv2)`, confirmed to match the exact quadratic form to ~1e-14 (vs ~2e-5 to ~2.6e-1 for `inprod()`). `tools/golden_r/core.R` now uses `inprod.bspline()` for those 4 cases; `core.json` regenerated (still 28 cases). No equivalent exact function exists in fda's public API for Fourier-basis or mixed-basis inner products (`inprod_fourier_L0_0/L1_1/L2_2`, `inprod_basis_bspline_x_fourier`) -- those remain at R's own ~1e-4 accuracy; cannot be tightened without either exposing private EPS/JMAX internals (not public API) or hand-deriving analytic Fourier integrals ourselves (would stop being "R's actual output").
- 2026-09-06 (Eng 1) `LDO` lives in `src/fabel/_operator.py` and is re-exported from `core.py` and `__init__.py`. `basis.py` needs `LDO` for penalties and `core.py` needs `Basis`, so a shared leaf module is the only way to break the cycle without a runtime import.
- 2026-09-06 (Eng 1) B-spline right-endpoint convention: the last knot interval is closed when `deriv == 0 or order - deriv > 1`. Evaluating at the right endpoint must reproduce the limit from the left; for the top derivative of a spline that limit does not exist, so the half-open convention is kept there.
- 2026-09-06 (Eng 1) Product bases carry knot multiplicities: the product of splines of orders `k1, k2` with interior smoothness `s1, s2` is order `k1 + k2 - 1` with multiplicity `order - 1 - min(s1, s2)`. Merging plain breaks gives a space that is too smooth and cannot hold the product (measured 6e-2 absolute error before the fix, 1e-15 after). This is where Fabel deliberately diverges from `times.fd`, which is 12.8% off the exact product.
- 2026-09-06 (Eng 1) `.derivative(n)` is exact everywhere: each basis reports `(derivative_basis, coefficient_matrix)` from `_derivative_map`. The derivative of an order-k spline is the order-(k-n) spline on the same breaks, so no projection and no accuracy loss. `deriv.fd` instead re-expands in the original basis and is 1.3% off.
- 2026-09-06 (Eng 1) `FData ** p`: non-negative integers are exact repeated products in the product basis; every other exponent is projected onto a spline refined eightfold at order 6, because no basis holds a fractional power exactly. `FData / FData` raises `TypeError` -- the quotient is not closed in any supported basis. `fd +/- scalar` uses the L2 projection of the constant.
- 2026-09-06 (Eng 1) `.std()` projects the pointwise ddof=1 standard deviation sampled on `max(201, 10 * n_basis)` points. Exact whenever the deviation lies in the span; the pointwise sd of an arbitrary sample generally does not, so this is a projection by nature, not an approximation choice.
- 2026-09-06 (Eng 1) `_backend.result_namespace` treats NumPy as promotable: with a torch argument and NumPy coefficients the result is torch. `array_api_compat.array_namespace` raises on that mix, but it is exactly what a torch user hits when evaluating a NumPy-fitted curve.
- 2026-09-06 (Eng 1) `_backend.asarray` returns its argument unchanged when namespace and dtype already match. This preserves autograd graphs (the documented contract) and avoids torch's `requires_grad` deprecation warning.
- 2026-09-06 (Eng 1) `inprod`'s operator parameters are named `lfd1`/`lfd2`, lowercase, to satisfy ruff N803 without a per-file ignore.
- 2026-09-06 (Eng 1) Parity comparisons use `atol = 1e-12 * max(1.0, max|expected|)`. This scales the absolute floor with the magnitude of the case rather than loosening `rtol`, which stays at the golden file's `meta.rtol`.
- 2026-09-06 (Eng 1) Core parity compares function values on a shared 401-point grid rather than coefficients, so a result landing in a different but equivalent basis still matches. Coefficient comparison would falsely fail every case where Fabel's exact derivative or product basis differs from R's.
- 2026-09-06 (Eng 1) 17 basis cases and 7 core cases are strict xfails because R fda 6.3.0 is the less accurate side. Each carries the measured deviation and the mathematics in the `R_FDA_DEFECTS` dicts of `tests/parity/test_basis.py` and `test_core.py`. Strict, so a future golden regeneration that fixes one fails the suite instead of passing silently -- this is how the four `inprod_bspline_*` cases were caught and un-xfailed the same day.
- 2026-09-06 (Eng 1) Penalty and Gram matrices are memoised globally on the basis value (`_linalg.cached_gram`), not per instance. `benchmarks/test_bench_basis.py` therefore clears the cache each round; a freshly constructed but equal basis is a cache hit, and timing it measured a dict lookup (8 us) instead of the quadrature (285 us).
- 2026-09-06 (Eng 1) Plot tests assert the vertex data handed to the renderer rather than an image hash. An image hash pins fonts, DPI, the matplotlib version and the platform, none of which the plotting code controls; comparing `Line2D.get_xydata()` against the curve values pins exactly what the mixin is responsible for and is stable across all of them.
- 2026-09-06 `pca.fd()$values` and `cca.fd()$ccacorr` are both the FULL eigenvalue/canonical-correlation spectrum (length = nbasis, or nbasis*nvar for a multivariate fd) -- only `harmonics`/`scores`/`varprop` (pca.fd) and `ccawtfd1/2`/`ccavar1/2` (cca.fd) are truncated to `nharm`/`ncan`. `tools/golden_r/decomposition.R` records the full spectra plus the truncated fields.

Field-name capitalization is inconsistent between the two paths (`bvar` embedded in scalar-response `fRegress()`, `Bvar` in standalone `fRegress.stderr()`) -- same quantity, different case.

## Failed approaches (do not retry)
- Naive B-spline penalty Lfdobj bound `Lfdobj < norder` (from initial task heuristic): fails for e.g. order 3, Lfdobj 2. Correct bound is `Lfdobj <= norder - 2`.
- Passing `fdnames` explicitly to `bifd()` to work around its 3-D `defaultnames` bug: does not help, since the crashing line (`names(defaultnames) <- ...`) never reads the `fdnames` argument. Must avoid ndim==3 arrays entirely (use ndim==2 or ndim==4).
- `jsonlite::toJSON(..., digits = NA)` as "full precision" for golden files: it is not (see Decisions above). Always use `digits = 17`.
- Representing scalar/dummy covariates in `fRegress`/`Fperm.fd`'s `xfdlist` as constant-basis `fd` objects with an all-constant `betalist`: produces a degenerate zero `Fobs` for a functional response (see Decisions above). Use a real functional basis for `betalist` instead.
- 2026-09-06 (Eng 1) `fd + scalar` requires the basis to span the constants. `_constant` projects the constant and checks the residual on the quadrature nodes, raising `ValueError` naming the basis when it is not reproduced. `Monomial(exponents=[1, 2])` was 1.0 off and `Exponential(rates=[1, 2])` 0.153 off, silently. Projecting "as well as possible" is the wrong answer for an operation whose meaning is exact; adding zero stays valid everywhere.
- 2026-09-06 (Eng 1) The fallback product basis (mixed families) is searched, not fixed: refinements 1..128 of the shared breaks x orders 8, 10, 12, accepting the first that reproduces every pairwise product `phi_i psi_j` to 1e-9, else raising. 12 is the ceiling because `_QUAD_DEGREE = 12` integrates products of order-12 splines exactly and no more. Raising the order buys accuracy far more cheaply than refining: two Fourier bases of different periods need 73 basis functions this way against ~263 by refinement alone. Interior knots inherit the multiplicity a spline factor's own continuity demands -- without that a C^2 kink caps the accuracy at 6e-8 no matter how fine the mesh.
- 2026-09-06 (Eng 1) `cov()` returns ONE `BiFData` for a multivariate `FData`, with the per-variable surfaces stacked on a trailing axis (`(n_basis, n_basis, n_vars)`), rather than a tuple. `BiFData` already carries trailing axes through evaluation, so one return type serves both cases and callers need no branch. Cross-variable covariances are deliberately not formed: they are a different object (a matrix of surfaces) and no R entry point returns them here. `std()` likewise keeps the variable axis, `(n_basis, 1, n_vars)`.
- 2026-09-06 (Eng 1) `Basis.__call__` raises on a 2-D `t` instead of flattening it, and reads a 0-d array as one point. Flattening turned a caller's `(n_s, n_t)` grid into `n_s * n_t` rows with no signal.
- 2026-09-06 (Eng 1) A penalty whose `LDO` carries a functional (`FData`) weight is not memoised: `FData` has `eq=False` so it hashes by identity, and the entry could never be hit again while still evicting useful ones from the FIFO cache. `LDO.is_constant` gates it.
- 2026-09-06 (Eng 1) Autograd rule for every coefficient-producing operation: quadrature nodes, design matrices and Gram matrices depend only on the basis, so they are built once in NumPy and converted with `asarray`; everything downstream of the coefficients stays in the inputs' namespace. `_promote` replaces `float()` coercion so a tensor scalar keeps its graph. `_backend.asarray` copies a read-only NumPy array before a foreign conversion, since torch refuses to wrap one.
- 2026-09-06 (Eng 1) A B-spline derivative caps each interior knot multiplicity at the reduced order rather than refusing. Above that the function already jumps and the next derivative carries a Dirac delta, which no basis expansion holds; capping returns the almost-everywhere derivative, which is what evaluation returns too, so `.derivative(n)(t) == fd(t, n)` stays true. Measured on `(fd*fd)` of order 7: D^3 jumps by -8625 at t=0.2.

## Blocked
- **(Eng 1) 4 core parity cases cannot be matched, upstream limit, not a Fabel defect.** `inprod_fourier_L0_0/L1_1/L2_2` and `inprod_basis_bspline_x_fourier` disagree with the exact integral by ~1.3e-4 relative, above core.json's 1e-6 rtol.
